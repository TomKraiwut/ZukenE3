Schematics: ออกแบบวงจรไฟฟ้าด้วย E3.schematic

พื้นฐานที่ต้องรู้ก่อนสร้างวงจรไฟฟ้าแรกของคุณ

1. หน้าตาโปรแกรม (User Interface)

เมื่อเปิดโปรแกรมและสร้างโปรเจกต์ใหม่ จะเจอหน้าต่างหลักๆ ตามคู่มือ E3.schematic ดังนี้

ส่วนประกอบหน้าที่
Project Windowโครงสร้างโปรเจกต์แบบ Tree แสดงชีท (Sheet), Device, Cable, Connector ทั้งหมด — ใช้ Jump to ไปยัง Object ที่ต้องการได้
Database Windowคลัง Symbol/Component ในฐานข้อมูล ค้นหาและลากมาวางบนชีทได้โดยตรง
Graphical Editor (Sheet)พื้นที่วาดวงจร วาง Symbol และลาก Connection เชื่อมกันที่นี่
Preview Window / 3D Preview Windowแสดงตัวอย่างกราฟิกของ Symbol/Component ก่อนวาง รวมถึงมุมมอง 3D ของอุปกรณ์
Properties Windowแก้ไขคุณสมบัติของ Symbol/Device ที่เลือกอยู่ เช่น Attribute, Item Designation
Output Window / Status Barแสดงข้อความแจ้งเตือนและผลของคำสั่งตรวจสอบ (เช่น Check Design)

2. Symbol, Component และ Device ต่างกันอย่างไร

E3.series เป็นระบบ Object-Oriented ที่ Symbol และ Component ทุกตัวเก็บอยู่ในฐานข้อมูลกลาง เมื่อ "วาง" (Place) ลงในโปรเจกต์ ระบบจะสร้างสำเนาเป็น Device แยกจากฐานข้อมูล ทำให้โปรเจกต์เป็นอิสระจากฐานข้อมูลต้นทาง (แก้ Device ในโปรเจกต์ไม่กระทบฐานข้อมูล) — ถ้าต้องการสร้าง Symbol/Component เองดูวิธีทำได้ที่หน้า Database Editor

Objectความหมาย
Symbolรูปกราฟิกแทนฟังก์ชันทางไฟฟ้า/นิวเมติก/ไฮดรอลิก ประกอบด้วย Graphic, Pin, Text Placeholder และ Attribute
Componentอุปกรณ์จริงที่นิยามไว้ในฐานข้อมูล อาจประกอบด้วย Symbol หนึ่งตัวหรือหลายตัว (เช่น รีเลย์ = ขดลวด + หน้าสัมผัสหลายชุด)
DeviceComponent ที่ถูกวางลงในโปรเจกต์แล้ว และได้รับ Item Designation เฉพาะตัว

Device ทุกตัวจะได้ Item Designation ตามมาตรฐาน IEC 81346 / DIN 40719 ประกอบด้วย 4 ส่วน:

สัญลักษณ์นำหน้าความหมาย
=Higher Level Assignment (HLA) — กลุ่ม/ระบบย่อยที่อุปกรณ์สังกัด
+Location — ตำแหน่งติดตั้งจริง เช่น ตู้คอนโทรลไหน
-Device Designation — หมายเลขอุปกรณ์ (ส่วนที่ใช้บ่อยที่สุด ถ้าใช้ตัวนี้ตัวเดียวสามารถละเครื่องหมาย - ได้)
:Pin Name — ชื่อขา/สายที่ต่อกับ Device นั้น

ลำดับเต็มคือ =HLA +Location -Device:Pin เช่น =K1+PANEL1-Q3:14 — ถ้าไม่กำหนด HLA/Location ให้กับ Sheet และ Device จะรับค่ามาจาก Sheet Header โดยอัตโนมัติ

3. สร้างวงจรแรก: สวิตช์ควบคุมหลอดไฟ

ทำตามขั้นตอนนี้เพื่อสร้างวงจรง่ายๆ แหล่งจ่ายไฟ → สวิตช์ → หลอดไฟ

  1. สร้างโปรเจกต์ใหม่ แล้ว Insert Sheet เลือก Sheet Format ที่ต้องการ (เช่น A3 Landscape)
  2. เปิด Database Window ค้นหาและลาก Symbol แหล่งจ่ายไฟ, สวิตช์, และหลอดไฟ มาวางบนชีท (Placing from the Database)
  3. กด C เพื่อใช้คำสั่ง Insert Connection แล้วคลิกขา (Pin) ของแต่ละ Symbol เรียงต่อกันเป็นวงจร — ถ้าเลือกหลายขาพร้อมกันด้วยกรอบสี่เหลี่ยม ระบบจะ Auto Route ให้อัตโนมัติ
  4. ดับเบิลคลิกแต่ละ Symbol เพื่อเปิด Properties Window แล้วตรวจสอบ Component Tab ว่าผูก Part จริงจากฐานข้อมูลไว้ครบ
  5. ตั้ง Item Designation ให้แต่ละ Device (HLA/Location/Device Designation) ให้สอดคล้องกับตำแหน่งติดตั้งจริง
  6. รันคำสั่ง Check Design เพื่อตรวจสอบความถูกต้องของวงจรก่อนออกแบบจริง
Tip: ถ้า Symbol ไม่มี Part ผูกไว้ รายงาน BOM/Wire List จะไม่สมบูรณ์ — ควรผูก Component ให้ครบทุก Symbol ตั้งแต่ขั้นตอนออกแบบ ไม่ใช่ค่อยมาเติมทีหลัง

4. Terminals และการเชื่อมต่อที่ใช้บ่อย

Terminal เป็น Component ชนิดพิเศษ เมื่อวางจาก Database Window ระบบจะสร้าง Device ชนิด Terminal Strip ให้อัตโนมัติ — ถ้าวาง Terminal ชนิดเดียวกันซ้ำหลายตัวจะถูกจัดเข้า Terminal Strip เดียวกัน แต่ถ้าวาง Terminal ต่างชนิดกัน ระบบจะแยกสร้าง Strip ใหม่ให้แต่ละชนิดโดยอัตโนมัติ ระบบยังตรวจจำนวนสายที่เข้าขั้ว และ Cross-Section ให้ด้วย ถ้าเกินที่กำหนดจะแจ้งเตือนที่ Status Bar (Terminal Strip เดียวกันนี้ยังใช้จัดวางจริงต่อได้ในหน้า Panel)

คีย์ลัดคำสั่ง
CInsert Connection (ลากเส้นเชื่อมต่อทีละเส้น กด Space หรือคลิกซ้ายเพื่อหักมุม)
Alt+CInsert Busbar Connection
BInsert Curve Connection
Shift + ลากสร้างเส้นเชื่อมต่อแนวทแยง (Diagonal Connection)
คลุมด้วยกรอบสี่เหลี่ยมConnect Multiple Connections Automatically (เชื่อมหลายขาพร้อมกันตามแนวนอน/ตั้ง)

5. ดูผลลัพธ์เบื้องต้น

หลังวาดวงจรเสร็จ ตรวจสอบผลได้จาก:

  • BOM (Bill of Materials) — รายการชิ้นส่วนทั้งหมดพร้อมจำนวนและ Part Number
  • Wire List — รายการสายไฟทั้งหมดพร้อมจุดต้นทาง-ปลายทาง
  • Cross-Reference Report — ตำแหน่งอ้างอิงของ Symbol ที่ปรากฏซ้ำในหลายชีท
ข้อควรระวัง: ต้องรัน Check Design (การตรวจสอบความสมบูรณ์ของวงจร) ทุกครั้งก่อน Generate รายงานหรือส่งออกไฟล์ ไม่งั้นอาจได้ BOM/Harness ที่ไม่ตรงกับวงจรจริง

6. ตัวอย่างฝึกทำ

ตัวอย่างที่ 1: วงจรสวิตช์-หลอดไฟอย่างง่าย

โครงสร้าง: Power Supply → Switch → Lamp → Ground

  • Symbol: 4 ตัว (Power Supply, Switch, Lamp, Ground)
  • Wire: 3 เส้นเชื่อมต่อเรียงตามลำดับ

คำถามฝึกคิด: วาดวงจรเสร็จแล้ว รัน Check Design ผ่านหมด แต่ BOM ที่ Generate ออกมาไม่มีราคาหรือผู้ผลิตของ Switch ปรากฏ เกิดจากอะไร?

เฉลย: Check Design ตรวจแค่ความถูกต้องทางไฟฟ้าของการเชื่อมต่อ ไม่ได้ตรวจว่าผูก Part ครบหรือไม่ — ต้องเปิด Symbol ของ Switch แล้วเลือก Part จาก Component Database ให้ครบก่อน BOM ถึงจะมีข้อมูลผู้ผลิตครบ

ตัวอย่างที่ 2: Connector หลายขาเชื่อมหลายชีท

โครงสร้าง: Connector (8-pin) เชื่อมสัญญาณจากชีท 1 ไปยังชีท 2-3

ใช้ Cross-Reference ติดตามว่าสัญญาณแต่ละขาของ Connector ไปโผล่ที่ชีทไหนบ้าง

คำถามฝึกคิด: ทำไมโปรเจกต์ที่มีหลายชีทถึงต้องพึ่ง Cross-Reference แทนการไล่ดู Wire ทีละเส้นด้วยตา?

เฉลย: เมื่อ Connector ตัวเดียวกันปรากฏในหลายชีท (เช่น ขาแต่ละขาต่อไปยังวงจรคนละส่วน) การไล่ตาจะพลาดง่ายและช้ามาก Cross-Reference จะอัปเดตอัตโนมัติทุกครั้งที่แก้วงจร ทำให้มั่นใจได้ว่าเอกสารตรงกับแบบจริงเสมอ
