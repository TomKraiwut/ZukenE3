Advanced: Database Editor และออกแบบ Cable Harness

งานขั้นสูงของ E3.series แบ่งเป็นสองเรื่องหลัก คือสร้าง Symbol/Component เองใน Database Editor เมื่อของในฐานข้อมูลมาตรฐานไม่พอ และใช้โมดูล E3.cable ออกแบบ Harness ให้พร้อมผลิตจริง (Mating Connector, Dynamic Cable, Block Function)

1. สร้าง Symbol/Component ด้วย Database Editor

เปิด Database Editor ได้จากคำสั่ง New Symbol / New Component ในเมนูคลิกขวาของ Database Window โปรแกรมจะเปิดหน้าต่างแยกต่างหาก สังเกตได้จากชื่อ E3.dbe บน Title Bar — โหมดนี้แก้ไข "ต้นแบบ" ในฐานข้อมูล โดยไม่กระทบ Device ที่วางไปแล้วในโปรเจกต์ และยังเปิดโปรเจกต์คู่ขนานไปพร้อมกันได้

Symbol Checklist (สร้าง Symbol ใหม่):

  1. กำหนด Symbol Properties — ชนิดและชื่อ Symbol
  2. Insert Symbol Graphic (รองรับ Import DXF/DWG) — กราฟิกแก้ไขไม่ได้อีกในโหมด Project
  3. วาง Node บนตำแหน่งที่ต้องการให้ Connection เข้ามาต่อ พร้อมกำหนดทิศทางการเชื่อมต่อ (Connection Direction)
  4. วาง Text Placeholder สำหรับข้อมูลที่ระบบ/ผู้ใช้จะเติมทีหลัง เช่น Item Designation
  5. ตรวจสอบ/กำหนด Space Requirement และ Symbol Origin (จุดอ้างอิงตอนวาง)

ส่วน Component ผูก Symbol เข้ากับข้อมูลอุปกรณ์จริง (Manufacturer, Part Number, จำนวนขา) — ฐานข้อมูลของ E3.series ยังรองรับ Component หลายชนิดที่มีพฤติกรรมต่างกัน เช่น Cable, Wire Group, Terminal, Connector, Busbar, Subcircuit และ Assembly ให้เลือกใช้ตามลักษณะอุปกรณ์จริง

ก่อนเริ่ม: อย่าสร้าง Symbol/Component ใหม่ซ้ำกับที่มีอยู่แล้ว — ค้นหาในฐานข้อมูลก่อนเสมอ และถ้าต้อง แก้ไขของเดิม ใช้คำสั่ง Symbol/Component Edit แล้วบันทึกทับชื่อเดิม ไม่ใช่สร้างใหม่ซ้ำซ้อน

2. Mating Connector และ Dynamic Cable (E3.cable)

เมื่อวงจร Schematic เสร็จแล้ว โมดูล E3.cable เพิ่มความสามารถด้าน Harness ให้ โดยยังใช้ฟังก์ชันของ E3.schematic ได้ทั้งหมด สองกลไกสำคัญที่ช่วยลดงานซ้ำคือ:

  • Mating Connector อัตโนมัติ — เมื่อลาก Connection เข้าฝั่งตัวเมีย/ตัวผู้ของ Connector ระบบจะวาง Active Mating Connector ที่กำหนดไว้ใน Component Properties ให้อัตโนมัติ และมีตัวเลือกบังคับให้เสียบได้ เฉพาะ Mating Connector ที่ถูกต้อง หรือเฉพาะ Pin Gender ที่เข้ากันได้เท่านั้น (ป้องกัน Harness ผิดตั้งแต่ขั้นออกแบบ)
  • Dynamic Cable — ต่างจาก Database Cable ตรงที่ปรับจำนวนแกนสาย (Conductor) และชื่อได้อิสระ (Insert → Cable) กำหนด Cross-Section, เส้นผ่านศูนย์กลาง และสีของแต่ละแกนได้ในภายหลัง และ Rename แกนสายเป็นชุด ด้วยค่าเริ่มต้น–ค่าสิ้นสุดในคำสั่ง Rename conductors/wires

3. Reuse วงจรด้วย Block Function (Dynamic Block)

Dynamic Block ใช้แทนฟังก์ชันที่ยังไม่นิยามครบ (Black Box) ในผังสาย — เป็นบล็อกที่ยังไม่มีอยู่ในฐานข้อมูลชิ้นส่วนและ ไม่ นับรวมใน BOM แต่ยังตั้ง Item Designation ให้ได้ ตั้งแต่เวอร์ชัน 2016 วาง Terminal, Connector และ Device ไว้ข้างในบล็อกได้ ไม่ใช่แค่ Block Connector บนขอบเหมือนเดิม

ถ้าต้องการให้บล็อกถูกนับใน BOM จริง ให้สร้างเป็น Component ชนิด Block ในฐานข้อมูลแทน — กำหนด Block Connector ล่วงหน้า และเลือก Symbol Type เป็น "Block" (ปรับขนาดได้หลังวาง) หรือ "Block fix" (ขนาดคงที่)

4. ออโตเมชันด้วย E3 API/Macro (เสริม)

นอกจาก Database Editor แล้ว E3.series ยังมี COM API (E3.Application) ให้เขียน Macro อัตโนมัติงานที่ทำซ้ำๆ ได้ เช่น ไล่ตรวจว่า Symbol ตัวไหนยังไม่ผูก Part — เหมาะกับงาน QA ก่อนส่งแบบ มากกว่าการแทนที่ Database Editor 

' ตัวอย่าง Macro (VBA-like) ตรวจสอบ Symbol ที่ยังไม่ผูก Part Number
Dim e3 As Object
Dim job As Object
Dim sym As Object
Dim symbols() As Long
Dim i As Integer

Set e3 = GetObject(, "CT.Application")
Set job = e3.CreateJobObject
job.GetAllSymbolIds symbols

For i = 0 To UBound(symbols)
    Set sym = e3.CreateSymbolObject
    sym.SetId symbols(i)
    If sym.GetPartId() = 0 Then
        Debug.Print "Missing part: " & sym.GetName()
    End If
Next i
Tip: ตั้งชื่อ Sheet, Wire Label และ Cable ให้เป็นระบบเดียวกันทั้งโปรเจกต์ (เช่น กำหนด Naming Convention ตั้งแต่ต้น) เพราะเมื่อโปรเจกต์มีหลายร้อยชีท การไล่หา Cross-Reference จะยากมากถ้าตั้งชื่อไม่เป็นระบบ
